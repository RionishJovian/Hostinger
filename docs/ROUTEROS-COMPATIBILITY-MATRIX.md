# Magic Connect RouterOS compatibility matrix

Status: initial software policy, not a MikroTik hardware certification. Last checked against the official MikroTik RouterOS Manual on 2026-10-09. Recheck upstream documentation and representative hardware before widening support claims.

## Runtime states

- Initial bootstrap review: an authenticated Owner/Admin may review and authorize the immutable, narrowly scoped bootstrap plan using available plan evidence and local technician checks. The response explicitly says `remote_device_verified: false`. This gate does not run or require RouterOS preflight and does not claim the router is compatible, connected, or remotely inspected.
- Post-connection preflight: available only after a fresh Hub handshake (currently at most 180 seconds old) and while the plan is `verifying_management` or `connected`. It performs certificate-verified HTTPS reads using the dedicated Monitoring identity, stores tenant/router-scoped evidence, and marks Connected only when the authenticated identity-bound management read is fresh and follows the handshake.
- `compatible_for_safe_change`: stable RouterOS v7+, recognized architecture, live WireGuard resource detected, and authenticated certificate-verified monitoring read. This is post-connection compatibility evidence only; it does not certify hardware or authorize writes. Safe Change additionally requires this evidence to be no more than 15 minutes old and to postdate the verified management read, plus its existing read/backup/confirmation gates.
- `needs_review`: missing/unknown evidence, prerelease version, unrecognized architecture, missing WireGuard capability, or transport/read evidence that is insufficient. Show the recorded reason and do not prepare a device configuration.
- `unsupported`: known RouterOS v6 or `mipsle` architecture. Show upgrade/device guidance; do not prepare a bootstrap or Safe Change plan.

No status in this matrix means the device is certified, connected, or operational. Actual support must be accumulated by RouterOS version, architecture, and representative model using real-device acceptance evidence.
